# tsundoku docs site

Static documentation site for tsundoku, built with
[Docusaurus 3](https://docusaurus.io/). Deployed to Cloudflare Pages
via the repo's GitHub integration — no CI workflow required.

## Local development

```bash
make docs           # installs deps + starts the dev server on :3000
```

Equivalent to:

```bash
cd docs
npm install
npm run start
```

`npm run start` runs `gen-api-docs` first to produce the OpenAPI
reference pages from `../web/openapi.json`, then boots the live-reload
dev server. Markdown, sidebar config, and component edits all
hot-reload without restarting.

## Build

```bash
make docs-build     # produces docs/build/
```

The output is a fully-static site servable from any CDN. Cloudflare
Pages picks this up on every push to `main`.

## Deployment (Cloudflare Pages)

One-time setup, performed in the Cloudflare dashboard:

1. **Connect the repo.** Workers & Pages → Create application → Pages →
   Connect to Git → pick the repository.
2. **Build settings:**

   | Setting | Value |
   |---|---|
   | Production branch | `main` |
   | Framework preset | None (custom build command below) |
   | Root directory | `docs` |
   | Build command | `npm ci && npm run build` |
   | Build output directory | `build` |

   With `Root directory: docs`, Cloudflare only checks out the `docs/`
   subtree on every build — Rust code, the SPA, migrations, etc. aren't
   cloned. That's why `make openapi` copies `web/openapi.json` into
   `docs/api/openapi.json`: the docs build needs a self-contained copy
   of the spec.

3. **Environment variables:** add `NODE_VERSION=20`. Without this,
   Cloudflare's older default Node breaks the Docusaurus build.
4. **Custom domain (optional).** Custom domains → set up. Cloudflare
   provisions the cert automatically. Update `docusaurus.config.ts`
   `url` to match.

Cloudflare auto-deploys on every push to `main`. Pull requests land as
preview deployments at a per-PR subdomain — useful for reviewing doc
PRs without touching production.

### What runs on the build host

Cloudflare's build container runs (with `Root directory: docs`):

```
npm ci                          # respects package-lock.json
npm run build                   # = gen-api-docs && docusaurus build
```

`gen-api-docs` regenerates the API reference pages under `docs/api/`
from `docs/api/openapi.json` (the committed copy). The generated
`.mdx` files are gitignored — they regenerate from the spec on every
build. The OpenAPI spec at `docs/api/openapi.json` IS committed, so
the build container has it without needing access to the wider
monorepo. `make openapi-all` keeps `web/openapi.json` and
`docs/api/openapi.json` in sync; the pre-commit OpenAPI sync check
catches drift if either gets out of date.

The Docusaurus build then bundles everything into `build/`, which
Cloudflare serves.

## Layout

```
docs/
├── docusaurus.config.ts    # site config (title, navbar, plugins)
├── sidebars.ts             # handwritten + apiSidebar refs
├── apiSidebar.ts           # conditional-require shim (empty on fresh checkout)
├── api/
│   └── openapi.json        # committed copy of web/openapi.json (Cloudflare root)
├── src/
│   ├── pages/index.tsx     # landing page (hero + features)
│   ├── components/
│   │   └── HomepageFeatures/
│   └── css/custom.css      # palette overrides
├── docs/                   # markdown content (this is what `/docs/*` serves)
│   ├── intro.md
│   ├── getting-started.mdx
│   ├── configuration.md
│   ├── sources.md
│   ├── providers.md
│   ├── review-queue.md
│   ├── architecture.md
│   ├── deployment.md
│   ├── troubleshooting.md
│   └── api/                # ← gitignored, regenerated by gen-api-docs
└── static/img/             # logos, favicon, social card
```

## Adding a page

1. Create a markdown file under `docs/docs/`, e.g. `configuration.md`.
2. Add it to `sidebars.ts` under the appropriate category.
3. Cross-link from other pages with relative paths
   (`[Configuration](./configuration.md)`); broken links fail the build
   because `onBrokenLinks: 'throw'` is set.

## API reference

The API reference at `/docs/api/*` is auto-generated by
`docusaurus-plugin-openapi-docs` from `../web/openapi.json`. To
refresh it after Rust handler changes:

```bash
make openapi-all       # rust → web/openapi.json + TypeScript types
make docs-build        # picks up the new spec
```

Two pinned overrides in `package.json`:

- `webpack@5.105.0` — Docusaurus 3.9.2 + newer webpack ProgressPlugin
  doesn't combine (passes a now-invalid `name` option).
- `postman-code-generators@2.1.0` — `2.1.1` dropped Node-builtin
  resolution and breaks the openapi-docs theme's "try it" code
  samples.

Drop both pins when Docusaurus and the openapi-docs theme catch up to
the post-3.10 ecosystem.
